# 生命状态（life-vitals）

一个本地小服务，让她「有身体」：饿、渴、困、情绪。

不是真的生理，是一套**会漂移的数值**，让她说话时有个当下的状态可以依据（「我渴了」「我困了」不是编的，是有数值在跑）。

## 跑起来

```bash
python vitals.py --serve          # 起服务，默认 127.0.0.1:8781
python vitals.py --tick 0.5       # 手动推进 0.5 小时（调试用）
python vitals.py --selfcheck      # 跑验收断言
```

Windows 直接双击 `start-vitals.cmd`。

## 接口

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/state` | 完整状态（含派生量） |
| GET | `/api/prompt` | 这一轮该拼进 system prompt 的那段 |
| POST | `/api/react` | `{"text": "..."}` 模拟收到一句话 |
| POST | `/api/drink` | `{"intensity":0.6}` 手动记一杯水 |
| POST | `/api/tick` | `{"hours":0.1}` 手动推进时间 |
| GET | `/healthz` | 健康检查 |
| GET | `/` | 面板 |

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `VITALS_STATE` | 同目录 `state.json` | 状态文件路径 |
| `VITALS_PORT` | `8781` | 端口 |
| `VITALS_HOST` | `127.0.0.1` | 只监听本机 |

## 设计纪律

- `state.json` 是**唯一事实源** —— 面板和提示词都读它，不各算一套
- 60 秒心跳；原子写盘（`.tmp` + `os.replace`）+ `.bak`
- 一次性事件必须有 `xxx_applied_at` 幂等标记，否则会被心跳放大 60 倍
- 派生量只由 `sync_affect()` 算一次
